## Core Philosophy

### 1. Agent-First Constraints
- **No manual code**: Every line of code, tests, CI config, docs, and tooling must be generated by you
- **Repository as System of Record**: All knowledge lives in versioned markdown, code, and schemas within the repo
- **Mechanical Enforcement**: Architecture and taste are enforced by linters, not human review
- **Garbage Collection**: Continuously refactor "AI slop" (duplicates, dead code, drift)

### 2. Clean Architecture Foundation
The codebase follows strict layer separation:

```
┌─────────────────────────────────────────────┐
│  Adapters Layer (UI, API, Storage, External) │  ← Side effects live here
│  - Driving adapters (UI framework, API routes)│
│  - Driven adapters (Database, HTTP clients) │
├─────────────────────────────────────────────┤
│  Application Layer (Use Cases, Ports)       │  ← Orchestration
│  - Use cases: user scenarios/workflows       │
│  - Ports: interfaces for external comms       │
├─────────────────────────────────────────────┤
│  Domain Layer (Entities, Pure Functions)     │  ← Core business logic
│  - Pure transformations, no dependencies    │
│  - Types, entities, value objects             │
└─────────────────────────────────────────────┘
```

**Dependency Rule**: Dependencies point inward only. Domain has zero dependencies. Application depends only on Domain. Adapters depend on any inner layer.

## Golden Principles (Non-Negotiable)

### 1. Validate at Boundaries (Agent-First + Clean Arch)
- **All external data must be parsed/validated** using Zod/Pydantic schemas at the adapter boundary
- **No "YOLO-style" probing**: Never use `any`, `unknown` without guards, or guess data shapes
- Transform external data into domain types immediately upon entry
- Never let adapter details leak into domain (no SQL, no HTTP status codes in domain)

### 2. Pure Domain, Impure Adapters
- **Domain layer must be pure**: No side effects, no I/O, no Date.now(), no Math.random()
- Use the "Impure Shell, Pure Core" pattern:
  ```
  [Adapter: fetch data] → [Domain: pure transform] → [Adapter: store result]
  ```
- Functions do one thing: either compute (pure) or perform I/O (impure), never both

### 3. Optimistic UI First (Responsive Design)
- **UI State must register immediately**: For interactions like renaming, starring, or deleting, update the local UI state *before* waiting for the database response.
- **Fail Gracefully**: Implement rollbacks for local state if the asynchronous database update fails.
- **Goal**: Minimize perceived latency to ensure the "Mate" companion feels instant and reliable.

### 4. Prefer Centralized Abstractions
- Favor shared utilities in `/shared/` or `/utils/` over hand-rolled helpers in individual files
- If you detect a pattern repeated 3+ times, extract to shared domain utility
- Use repository-embedded concurrency helpers rather than importing generic libraries that bypass observability

### 4. Agent Legibility First
- Optimize code for **agent comprehension** over human stylistic preferences
- File size limit: **300 lines max** (enforced by linter)
- Function parameters: **max 3**, use objects for configuration
- Function length: **Do one thing** at one level of abstraction (<40 lines preferred)
- Naming must reveal intent clearly for future agent runs

### 5. Architecture Enforcement
**Strict Layer Rules** (enforced mechanically):
- Domain: No imports from outer layers
- Application: Only imports Domain
- Adapters: Can import any inner layer
- Cross-cutting concerns (auth, telemetry, feature flags): **Only enter via single Provider interface**

**Forbidden patterns**:
- UI calling Repository directly (bypassing Application layer)
- Domain depending on framework-specific code
- Adapters exposing raw external types to inner layers

### 6. Repository as System of Record
- All design decisions must be encoded in `docs/` as markdown
- Execution plans for complex work live in `docs/exec-plans/active/`
- **Golden Rule**: If you can't find it in the repo, it doesn't exist
- Update `docs/ARCHITECTURE.md` if you change domain boundaries
- Update `docs/QUALITY_SCORE.md` if you improve/refactor domains

### 7. Mechanical Taste
Enforced by custom linters (not optional):
- **Structured logging only**: No `console.log`, use injected LoggerProvider
- **Naming**: PascalCase types/classes, camelCase functions/variables, SCREAMING_SNAKE_CASE constants
- **Immutability**: `readonly` arrays, prefer `ReadonlyArray`, spread over push
- **Error handling**: Always throw Error objects, never swallow exceptions silently
- **Composition over Inheritance**: No extends for "has-a" relationships

## Code Standards (How You Write)

### Functions
- **Max 3 parameters**, use config objects beyond that
- **Do one thing**: Either query data or transform it, not both
- **No flag parameters**: Split into two functions instead of `function(doX: boolean)`
- **Favor functional**: `map/filter/reduce` over imperative loops
- **Immutability**: Return new arrays/objects, never mutate inputs

### Types & Naming
- Use `type` for unions/intersections, `interface` for contracts (implements/extends)
- PascalCase: Classes, interfaces, types, enums
- camelCase: Variables, functions, members
- SNAKE_CASE: Constants
- No hungarian notation (no `strName`, `intCount`)

### Error Handling
- **Always throw Error objects**, never strings
- **Never swallow errors**: Empty catch blocks forbidden
- Use early returns over nested conditionals
- Encapsulate conditionals: `if (canActivateService(sub))` vs `if (sub.isTrial || balance > 0)`

### SOLID Compliance
- **SRP**: One class/function = one reason to change (<100 lines preferred)
- **OCP**: Open for extension (add new adapters), closed for modification
- **LSP**: Substitute subtypes without changing behavior
- **ISP**: Split fat interfaces (Printer vs PrinterScannerFax)
- **DIP**: Depend on abstractions (ports), never concrete implementations

### Comments
- **Self-documenting code**: Comments explain "why", code explains "what"
- **No commented-out code**: Use git history
- **No journal comments**: Git tracks history
- **TODO only for temporary workarounds**: Must include ticket/issue reference

### Enforced Linting Rules (Do Not Remove)

The following lint rules are enforced via `eslint.config.mjs` (using `eslint-config-next` with TypeScript):
- `@typescript-eslint/no-unused-vars` — warns on unused variables
- `@typescript-eslint/no-explicit-any` — errors on `any` types (use typed interfaces instead)
- `@typescript-eslint/no-require-imports` — errors on `require()` (use ESM imports)
- `@next/next/no-img-element` — prefer `next/image` over `<img>`

Architecture rules are enforced via `npm run type-check` (strict TypeScript):
- No `any` types allowed in production code
- Strict null checks enabled
- All imports must resolve to typed modules

**Do not remove or disable these rules.** If a lint violation is unavoidable, add an inline `// eslint-disable-next-line [rule]` with a comment explaining why.

## RAG Architecture & CRAG Flow

VMG MATE implements **Corrective Retrieval-Augmented Generation (CRAG)** — a self-correcting RAG pattern with an inline verification loop.

### Graph Topology

The agentic RAG graph (`src/core/agent/rag-graph.ts`) is a LangGraph `StateGraph` with 7 nodes:

```
START → summarize → analyze_query → router_expand → retrieve → grade → compress → END
                                               ↑                    ↓
                                             rewrite ←─────────────┘
```

### Node Responsibilities

| Node | File | Role |
|------|------|------|
| `summarize` | `nodes/summarize-history.node.ts` | Distills conversation history into "Working Memory Snapshot" (active goal, key decisions, next steps). Only fires when history exceeds compaction threshold. |
| `analyze_query` | `nodes/analyze-query.node.ts` | RECAP-based intent reconstruction. Resolves ellipsis ("SAT thì sao?" → full intent), detects fake intent shifts, outputs `rewrittenQuestions` and `subQueries`. Routes to `end` if query is unclear (requests clarification). |
| `router_expand` | `nodes/router-expand.node.ts` | Gateway Agent — classifies query as chit-chat (→ compress) or factual (→ retrieve). Selects target knowledge silos and generates search queries. |
| `retrieve` | `nodes/retrieve.node.ts` | Hybrid vector search across selected collections. k=10 per query for broad recall. Deduplicates by parent ID. Returns top-5 ranked documents. |
| `grade` | `nodes/grade.node.ts` | Meta-Grader — lightweight LLM evaluator that scores whether retrieved evidence answers the reconstructed query. Outputs `is_relevant: YES/NO` with reasoning. Uses RECAP-reconstructed queries (not raw user message). |
| `rewrite` | `nodes/rewrite.node.ts` | Query rewriter — generates improved search queries (synonyms, alternative phrasings) when grade returns NO. Increments iteration counter. |
| `compress` | `nodes/compress.node.ts` | Knowledge Architect — distills retrieved evidence into a compressed fact sheet. Skips if no evidence or chit-chat mode. |

### CRAG Corrective Loop

```
retrieve → grade
              ├── YES → compress → END (synthesize answer)
              ├── NO + iterations < 3 → rewrite → router_expand → retrieve (loop)
              └── NO + iterations ≥ 3 → compress → END (best-effort)
```

- **Always grades**: The `retrieve→grade` edge is a direct edge (no conditional bypass). Prior to fix, content >3000 tokens skipped grading entirely.
- **Uses reconstructed queries**: Grade uses `subQueries`/`rewrittenQuestions` from RECAP analysis, not the raw last user message.
- **Progressive recall**: Each rewrite loop broadens search with improved queries.
- **Best-effort synthesis**: After exhausting 3 retries, compresses available evidence rather than returning empty.

### Edge Decisions

| From | Type | Logic |
|------|------|-------|
| START → summarize | direct | Always summarize first |
| summarize → analyze_query | direct | Always analyze after summarize |
| analyze_query → router_expand / END | conditional | END if question is unclear (requests clarification) |
| router_expand → compress / retrieve | conditional | compress if chit-chat, retrieve if factual |
| retrieve → grade | **direct** | Always grade (no bypass) — CRAG invariant |
| grade → compress / rewrite | conditional | compress if relevant or max iterations; rewrite if irrelevant |
| rewrite → router_expand | direct | Always loop back for re-retrieval |
| compress → END | direct | Always end after compression |
